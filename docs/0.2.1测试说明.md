# 火花助手 0.2.1 测试说明

本版修复 0.2.0 的真实富文本输入框兼容问题，并按用户最新要求恢复后台执行、允许主动再次发送。纯本地、MIT，无服务器和检查更新。

## 改动与操作

- 只有“打开官网登录”弹出官方浏览器。检查登录、读取好友、单人／批量／定时发送均在后台执行，软件显示进度。遇官方验证时暂停并提示手动登录，不自动弹窗或绕过验证。
- 每条定时配置每天仍只执行一次；第一次手动发送会占用当天定时。此后可主动再次发送，新消息使用当前配置并取得独立请求编号。
- 前次结果已核对时显示“再次发送”。前次结果未知时显示“核对后再次发送”，确认具体旧记录后才创建新消息；旧记录保留，不被重试或改写。
- 排队或执行中仍禁止双击重复入队。明确未提交的失败显示“重试原消息”，重试原请求和原正文。重启后的未执行手动批次仍需主动继续，跨天跳过。
- 修复抖音编辑器自动追加的占位字符误触发正文保护。只排除已观察到的官方末端占位节点，不删除用户正文中的零宽字符、空格或换行，不放宽收件人和日期检查。
- 错误保留具体已知原因和固定阶段，避免所有情况只显示泛化的“可能已提交”。实际结果不能可靠核对时仍显示待核对，不把点击发送当成送达或续火花成功。

## 真实页面证据与边界

2026-10-18 只读检查安装版近期记录，发现两条手动任务均进入 `submission_uncertain`。随后在安装版自己的登录资料下，以后台模式确认账号、读取已有聊天列表并定位对应会话成功。

无提交诊断临时填入失败任务的原正文：页面正文比原文多一个 `U+200B`，位于最后的 `.ace-line > span[data-enter="true"][data-leaf="true"][data-string="true"]`。原校验返回 false，精准识别该占位后返回 true；用户正文节点中的零宽字符保留。诊断未按 Enter、未点击发送、未写入发送账本。

另观察到官方富文本对 `fill("")` 没有清空正文；同账号、同会话、同输入框和本次确切正文核验后，原生全选／退格可清除本次草稿。修复后的生产清理方法在真实页面返回成功，立即、350 毫秒和 1 秒后均只剩空输入框占位。清理保护不允许覆盖用户已修改的内容。

用户随后明确授权向测试好友发送一条指定文字。最终冻结 0.2.1 工作进程后台重新读取目录，确认唯一目标及账号身份，实际只调用一次发送；刷新后可见我方同文消息。返回 `message_unverified`、阶段 `verifying_persistence`，原因是官网缺少可靠的稳定消息标识，不能唯一关联本次发送。没有自动重发；手机端是否出现刚刚的新消息尚待用户确认。这与修复前被正文保护拦住的阶段不同，不能把“待核对”直接当成发送失败或送达成功。

好友目录仍仅代表网页已加载的一对一会话；本次真实读取返回部分结果，没有把它标为完整好友名单。未读到目标时先在抖音手动聊一次再刷新。

## 数据升级

数据库升级到 v3，升级前自动创建原版本备份。旧任务、账号身份和历史执行 ID 保留；每日实例仍有唯一约束，额外手动请求使用独立记录。同一点击操作有持久化幂等编号，重复到达或并发不会产生额外消息。

安装前退出旧版托盘程序；安装时不会自动重发历史未知消息。升级后不要用旧版程序打开 v3 数据库。Windows 默认资料仍位于 `%LOCALAPPDATA%\SparkAssistant`，源码包不包含这些资料。
